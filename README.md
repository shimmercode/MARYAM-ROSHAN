# سامانه جامع سالن زیبایی مریم روشن

سامانه یکپارچه مدیریت سالن زیبایی: رزرو نوبت، پرونده ۳۶۰ درجه مشتری، صندوق فروش،
حسابداری، انبار، پورسانت پرسنل، باشگاه مشتریان، بازاریابی خودکار و وب‌سایت عمومی سئو‌شده.

تمام رابط کاربری فارسی و راست‌به‌چپ است، تاریخ‌ها به صورت **شمسی** نمایش داده می‌شوند و
به صورت **میلادی** در پایگاه داده ذخیره می‌گردند.

## پشته فناوری

| لایه | فناوری |
|---|---|
| زبان | PHP 8.2+ (بدون فریم‌ورک، MVC سبک اختصاصی) |
| پایگاه داده | MySQL 8+ / MariaDB 10.6+ با PDO و Prepared Statements |
| رابط کاربری | Bootstrap 5.3 RTL (شبکه و اجزای پایه) + Tailwind-utilities (فاصله و چیدمان) |
| جاوااسکریپت | Vanilla ES6 Modules + Fetch API — بدون jQuery و بدون بیلد |
| نمودار | Chart.js (فقط در صفحات داشبورد و گزارش) |
| فونت | Vazirmatn (میزبانی محلی، بدون CDN) |

هیچ وابستگی به Composer، npm، Docker یا سرویس ابری برای اجرا لازم نیست.
تمام فایل‌های شخص ثالث در `public/assets/vendor/` میزبانی محلی شده‌اند.

## نیازمندی‌های سرور

- PHP **8.2** یا بالاتر
- افزونه‌های: `pdo_mysql`, `mbstring`, `json`, `openssl`, `fileinfo`, `gd` (اختیاری، برای تصاویر)
- MySQL **8.0+** یا MariaDB **10.6+**
- Apache با `mod_rewrite` فعال و `AllowOverride All`
- دسترسی نوشتن روی پوشه `storage/` و `public/uploads/`

## نصب

```bash
git clone https://github.com/shimmercode/MARYAM-ROSHAN.git
cd MARYAM-ROSHAN
cp .env.example .env
```

سپس مقادیر `.env` را تنظیم کنید (حداقل `DB_*` و `APP_URL`) و دسترسی‌ها را بدهید:

```bash
chmod -R 775 storage public/uploads
```

برای توسعه محلی:

```bash
php -S 0.0.0.0:8000 -t public
```

حالا مرورگر را روی `http://localhost:8000/install` باز کنید. نصاب در چهار گام:

1. **خوش‌آمد** — معرفی فرآیند
2. **بررسی نیازمندی‌ها** — نسخه PHP، افزونه‌ها و دسترسی پوشه‌ها
3. **پایگاه داده** — اتصال، ساخت جداول از `database/schema.sql` و درج داده‌های پایه از `database/seeds.sql`
4. **حساب مدیر** — نام، موبایل و رمز عبور مدیر ارشد را **خودتان** تعیین می‌کنید

> **هیچ رمز عبور پیش‌فرضی در مخزن وجود ندارد.** حساب مدیر ارشد فقط در گام چهارم نصب و با
> رمزی که خودتان وارد می‌کنید ساخته می‌شود (`password_hash` با bcrypt cost=12).
> برای توسعه محلی می‌توانید مثلاً موبایل `09120000000` و رمز دلخواه قوی انتخاب کنید.

پس از اتمام، فایل `storage/installed.lock` ساخته می‌شود و مسیر `/install` **به‌صورت خودکار
غیرفعال** می‌گردد. برای نصب مجدد باید این فایل را دستی حذف کنید.

داده‌های نمونه فارسی (خدمات، دسته‌بندی، سطوح وفاداری، قالب‌های پیامک، صفحات سایت) در گام
سوم درج می‌شوند. هیچ داده‌ای با نام‌های ساختگی انگلیسی وجود ندارد.

## ساختار پروژه

```
app/
├── core/           هسته: Router, Request, Response, Database, View, Session, Csrf, Env, Config, Logger
├── controllers/    نازک؛ فقط اعتبارسنجی ورودی، فراخوانی سرویس و بازگرداندن پاسخ
│   ├── admin/      پنل مدیریت
│   ├── customer/   پرتال مشتری
│   ├── staff/      پرتال پرسنل
│   ├── api/        REST API داخلی
│   ├── public_/    وب‌سایت عمومی
│   └── install/    نصاب
├── services/       منطق کسب‌وکار (تراکنش‌ها، محاسبات، قوانین)
├── repositories/   پرس‌وجوهای پیچیده و صفحه‌بندی
├── models/         موجودیت‌های پایه
├── middleware/     Auth, Guest, Csrf, Role, Permission, RateLimit, Installed, NotInstalled
├── validators/     اعتبارسنج با پیام‌های فارسی
├── helpers/        Jalali (تبدیل تقویم)، Format (اعداد/پول)، توابع سراسری
├── views/          قالب‌ها (بدون SQL و بدون منطق کسب‌وکار)
└── config/         —
config/             app.php, database.php, auth.php, services.php
database/           schema.sql (۱۱۴ جدول)، seeds.sql، migrations/
routes/             web.php، api.php
public/             تنها پوشه قابل دسترس از وب؛ index.php + assets
cron/               bootstrap.php، daily.php، reminders.php
storage/            logs، cache، exports، invoices، backups (خارج از دسترس وب)
tests/              مجموعه تست سبک PHP
tools/              ابزار توسعه
```

قواعد رعایت‌شده:

- هیچ `SELECT *` در کوئری‌های کاربردی؛ ستون‌ها صریح انتخاب می‌شوند.
- مبالغ همگی `DECIMAL(12,2)` هستند — هیچ `FLOAT`ی برای پول استفاده نشده است.
- هیچ SQL یا منطق کسب‌وکاری در لایه View وجود ندارد.
- کنترلرها نازک‌اند؛ منطق در سرویس‌ها و پرس‌وجوها در ریپازیتوری‌هاست.

## ماژول‌ها

### پنل مدیریت `/admin`

- **داشبورد** — شاخص‌های کلیدی، نمودار درآمد، نوبت‌های امروز، هشدارها، اقدامات سریع
- **مشتریان** — فهرست با فیلتر، فرم ثبت/ویرایش، و پرونده ۳۶۰ درجه شامل نوبت‌ها،
  فاکتورها، پرداخت‌ها، خدمات دریافتی، یادداشت‌ها، امتیاز وفاداری، کیف پول، نظرات و
  خط زمانی فعالیت
- **نوبت‌ها** — فهرست، تقویم، ویزارد رزرو چندمرحله‌ای و صفحه جزئیات با تاریخچه وضعیت
- **خدمات** — خدمات، دسته‌بندی‌ها و فرم شامل تخصیص پرسنل/شعبه و **رسپی مصرف کالا**
- **کارکنان** — فهرست، فرم (شامل ویرایشگر شیفت هفتگی و ساخت حساب کاربری) و پرونده
  عملکرد شامل پورسانت دوره و ارزیابی‌ها؛ پرونده هر پرسنل همچنین شامل چهار تب فرم زنده
  و قابل‌ذخیره در دیتابیس است: **آفر در لحظه**، **گزارش سفر مشتری**، **جدول مدیریت
  مشتریان** (گزارش دوره‌ای مقایسه‌ای) و **ارزیابی عملکرد** (بر پایه رابریک رسمی
  ۱۶‌شاخصی و جدول رتبه‌بندی/پاداش، با محاسبه خودکار نتیجه عملکرد و رتبه)
- **صندوق (POS)** — کاتالوگ خدمات/کالا، سبد، جستجوی مشتری، تخفیف، مالیات و تسویه
- **فاکتورها** — فهرست، جزئیات، ثبت پرداخت و نسخه چاپی
- **انبار** — سطح موجودی به تفکیک شعبه، مدیریت کالا، اصلاح دستی و دفتر گردش کامل
- **بازاریابی** — کمپین پیامکی با بخش‌بندی مخاطب، اتوماسیون «رویداد ← شرط ← اقدام» و کدهای تخفیف
- **گزارش‌ها** — فروش، نوبت، پرسنل، مشتری و انبار با بازه دلخواه، نمودار و خروجی CSV
- **ورود اطلاعات** — بارگذاری CSV با پیش‌نمایش و **گزارش خطای سطر‌به‌سطر** پیش از ثبت نهایی
- **تنظیمات** — پیکربندی عمومی/رزرو/مالی/وفاداری/اطلاع‌رسانی/سئو، شعبه‌ها، کاربران و
  نقش‌ها، پشتیبان‌گیری، گزارش فعالیت‌ها (Audit Log) و **آیین‌نامه و اسناد** (بارگذاری
  و دانلود اسناد PDF/Word/PowerPoint/Excel به‌صورت فایل‌های محافظت‌شده خارج از مسیر عمومی)

### موتور نوبت‌دهی

محاسبه بازه‌های آزاد بر اساس شیفت هفتگی پرسنل، مدت خدمت و زمان بافر.
ثبت نوبت داخل **تراکنش پایگاه داده** با قفل‌گذاری انجام می‌شود تا رزرو همزمان
(double booking) در سطح سرور غیرممکن باشد — نه فقط با اعتبارسنجی سمت کلاینت.

### مالی

فاکتور، اقلام، پرداخت چندروشی (POS، نقد، کارت‌به‌کارت، کیف پول، آنلاین)، تخفیف، مالیات
و کیف پول. **تاریخچه مالی هرگز حذف نمی‌شود**؛ استرداد وجه به‌صورت تراکنش جبرانی
(compensating transaction) ثبت می‌گردد.

### پورسانت

موتور پیکربندی‌پذیر با انواع درصدی، ثابت، پلکانی یا بدون پورسانت. محاسبات در جدول
`commissions` به تفکیک دوره (`YYYY-MM`) **ذخیره** می‌شوند تا گزارش‌ها بازتولیدپذیر باشند.

### باشگاه مشتریان

سطوح برنزی، نقره‌ای، طلایی و VIP — آستانه‌ها و ضرایب همگی از تنظیمات قابل تغییرند.

### پیامک

لایه انتزاعی با درایورهای **Kavenegar** و **Melipayamak**. بدون کلید API، درایور `log`
فعال است و پیام‌ها در `storage/logs/` ثبت می‌شوند؛ بنابراین کل سامانه بدون اعتبارنامه
هم کاملاً قابل استفاده است. کلیدها فقط از `.env` خوانده می‌شوند.

### پرتال مشتری `/customer` و پرتال پرسنل `/staff`

طراحی موبایل-اول با نوار ناوبری پایین. مشتری: نوبت بعدی، تاریخچه، امتیاز، کیف پول، ثبت
نظر. پرسنل: برنامه روز، برنامه هفته، پورسانت و عملکرد.

### وب‌سایت عمومی

`/`، `/services`، `/services/{slug}`، `/team`، `/gallery`، `/blog`، `/contact`، `/booking`
به‌همراه `sitemap.xml`، `robots.txt` و داده‌های ساخت‌یافته **JSON-LD** برای سئو.

### REST API داخلی `/api/v1/*`

پاسخ‌ها همیشه در پوشش یکسان برمی‌گردند:

```json
{ "success": true,  "data": { } }
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "..." } }
```

## نقش‌ها و دسترسی‌ها

| نقش | توضیح |
|---|---|
| `SUPER_ADMIN` | دسترسی کامل |
| `ADMIN` | مدیریت کامل به‌جز تنظیمات حساس |
| `BRANCH_MANAGER` | محدود به داده‌های شعبه خود |
| `RECEPTION` | نوبت، مشتری، صندوق و فاکتور |
| `SPECIALIST` | فقط برنامه و عملکرد خود |
| `CUSTOMER` | پرتال مشتری |

کنترل دسترسی بر پایه **مجوز** (نه صرفاً نقش) و **در سمت سرور** اعمال می‌شود؛ مخفی‌کردن
دکمه در رابط کاربری هرگز تنها سد دسترسی نیست.

## کران‌جاب‌ها

```cron
# نگهداری شبانه: تجمیع آمار، RFM، عدم مراجعه، تولدها، هشدار انبار، پشتیبان، پاک‌سازی
30 2 * * *  /usr/bin/php /path/to/cron/daily.php >> /dev/null 2>&1

# یادآوری نوبت‌ها (هر ساعت)
0 * * * *   /usr/bin/php /path/to/cron/reminders.php >> /dev/null 2>&1
```

هر وظیفه ایزوله اجرا می‌شود؛ شکست یک کار مانع اجرای بقیه نمی‌شود و در
`storage/logs/cron-YYYY-MM.log` ثبت می‌گردد.

## امنیت

- رمزها با `password_hash` (bcrypt، cost=12) — هیچ رمزی لاگ نمی‌شود
- نشست امن: `httponly`, `samesite`, بازتولید شناسه پس از ورود
- محدودیت تلاش ورود و میان‌افزار `RateLimit`
- توکن **CSRF** روی تمام فرم‌ها و درخواست‌های تغییردهنده
- خروجی همه‌جا با `e()` فرار داده می‌شود (XSS)
- تمام کوئری‌ها Prepared Statement — بدون الحاق رشته ورودی کاربر
- اعتبارسنجی نوع MIME و حجم فایل‌های بارگذاری‌شده
- هدرهای امنیتی و غیرفعال‌سازی فهرست دایرکتوری
- `Audit Log` برای عملیات حساس
- `.env` هرگز کامیت نمی‌شود (در `.gitignore`)
- تنها پوشه `public/` از وب قابل دسترسی است

## تست‌ها

PHPUnit روی محیط هدف (هاست اشتراکی بدون تضمین Composer) قابل نصب تمیز نبود، بنابراین
مجموعه تست به‌صورت اسکریپت‌های سبک PHP با یک assertion helper پیاده‌سازی شده است:

```bash
php tests/run.php
```

خروجی فعلی: **۵۹ بررسی — ۵۹ موفق، ۰ ناموفق** (تقویم جلالی، قالب‌بندی اعداد و پول،
مسیریاب، اعتبارسنج، CSRF و پیکربندی). تست‌های نیازمند پایگاه داده در صورت نبود اتصال
به‌صورت خودکار **skip** می‌شوند تا اجرای مجموعه هرگز به‌دروغ قرمز/سبز نشود.

## استقرار روی هاست اشتراکی

1. کل پروژه را آپلود کنید.
2. **Document Root** دامنه را روی پوشه `public/` تنظیم کنید.
   اگر میسر نبود، فایل `.htaccess` موجود در ریشه، درخواست‌ها را به `public/` هدایت می‌کند.
3. `.env` بسازید و `APP_ENV=production` و `APP_DEBUG=false` قرار دهید.
4. دسترسی نوشتن روی `storage/` و `public/uploads/` بدهید.
5. `/install` را اجرا کنید و پس از اتمام مطمئن شوید `storage/installed.lock` ساخته شده است.
6. کران‌جاب‌ها را از کنترل‌پنل هاست تنظیم کنید.

## ارتقا از نسخه قبلی

برای نصب‌های موجود (نصب‌شده با نسخه‌های قبل از ۰.۱.۴) که نمی‌خواهند/نمی‌توانند نصاب را
دوباره اجرا کنند:

1. از پایگاه داده نسخه پشتیبان بگیرید (تنظیمات › پشتیبان‌گیری یا از طریق phpMyAdmin).
2. فایل `database/upgrade_0.1.4.sql` را از طریق phpMyAdmin (یا `mysql < database/upgrade_0.1.4.sql`)
   روی پایگاه داده اجرا کنید. این اسکریپت idempotent است — جدول‌های جدید
   (`documents`, `instant_offers`, `customer_journey_entries`,
   `customer_management_reports`, `performance_evaluation_items`) و ستون‌های جدید
   جدول `performance_evaluations` (`special_score`, `rank_label`) را اضافه می‌کند
   و روی جدول‌ها/ستون‌های موجود خطا نمی‌دهد.
3. فایل‌های جدید پروژه (کد PHP و ویوها) را جایگزین نسخه قبلی کنید.
4. پوشه `storage/documents/` باید توسط وب‌سرور قابل‌نوشتن باشد (همانند `storage/backups/`).
5. اختیاری: با `php` (نمونه در دایرکتوری توسعه در `seed_documents.php` مستند شده)
   یا به‌صورت دستی از طریق «تنظیمات › آیین‌نامه و اسناد»، اسناد اولیه را بارگذاری کنید.
6. مقدار `version` در `config/app.php` را با کد منتشرشده جدید (۰.۱.۴) هماهنگ نگه دارید.
